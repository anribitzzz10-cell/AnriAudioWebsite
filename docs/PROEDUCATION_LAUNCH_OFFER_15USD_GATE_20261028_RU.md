## Обязательная архитектура
1. Server-side POST /v1/checkout/proeducation/create принимает только sku, buyer email, consent; создаёт непрогнозируемый order ID и фиксирует серверную цену (SKU + currency + integer minor units) со статусом pending.
2. Backend, а не браузер, подписывает поля для https://anriprod.proeducation.kz/ согласно реальному Hmac.php / договорённому sys, URL оплаты и currency. На сайте никогда нет merchant signing secret.
3. ProEducation отправляет callback на выделенный HTTPS backend URL. Сверить Sign HMAC с вендорским тест-вектором, merchant domain/sys, фиксированный order ID, сумму, SKU/quantity и независимо установленную валюту. Не доверять return URL или Moneta DEMO.
4. При успехе атомарно записать provider transaction + order paid + единственную бессрочную FULL license (idempotency + Postgres row locking). Ни demo, ни отсутствие подтверждения валюты/суммы не должны выдавать ключ.
5. Выдача ключа покупателю только через подтверждённую email-доставку / безопасный личный просмотр после проверки принадлежности заказа. Устойчиво к повторам, отказам отправки и возвратам. Не возвращать ключ просто по общедоступному order ID.
6. Плагин релизной сборки должен проверять production Ed25519 ключ (НЕ staging). Нужны подписанный и нотариализованный .pkg, тесты в чистой macOS, инструкции и проверенные условия возврата/покупки.
