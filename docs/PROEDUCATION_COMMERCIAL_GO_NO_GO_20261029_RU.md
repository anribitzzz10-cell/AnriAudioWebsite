# ANRI AUDIO MIDI — коммерческий checkout: GO / NO-GO (29.10.2026)

**Решение: NO-GO.** Это живой технический чек-лист к PR #22 сайта и PR #26 сервера, не разрешение на включение реальных платежей. Цена продукта — **$39 USD, разовая бессрочная FULL-лицензия без DEMO**, максимум 2 активированных устройства. Фактическая фиксированная сумма списания в KZT ещё не утверждена; тестовые 6500.00 KZT, 456.00 KZT и 100.00 KZT не являются ценой продукта.

## Что реализовано в PR

- На `/checkout/`, `/ru/checkout/`, `/kk/checkout/` готов закрытый по умолчанию интерфейс. `checkout/config.js`: `API_ORIGIN = ''`, `CHECKOUT_ENABLED = false`.
- Сайт принимает **только** созданную сервером подписанную форму заказа для `https://anriprod.proeducation.kz/`: `sys=anriaudio`, `currency=kzt`, товар `ANRI_AUDIO_MIDI_MAC_AUV2`, одна позиция, фиксированная сумма, проверенные адреса возврата. Браузер не задаёт цену и не подписывает запрос.
- Покупатель до оплаты сохраняет **номер заказа и отдельный 43-символьный приватный claim-код**. Кнопка копирует оба значения вместе (EN/RU/KK). Код не добавляется к URL, не отправляется почтой, не используется в query или cookie. Сайт хранит его лишь в `sessionStorage` текущей сессии; пользователь обязан сохранить копию самостоятельно.
- Только **подписанный серверный webhook** с проверкой `Sign`, `domain`, `sys`, `order_num`, статуса, корзины, суммы и провайдерского ID приводит к атомарной выдаче ровно одной лицензии в PostgreSQL. Возврат браузера от провайдера не подтверждает оплату.
- Защищённый `POST /v1/checkout/proeducation/claim` после оплаты возвращает **тот же зашифрованно сохранённый FULL-ключ**; восстановление не создаёт новую лицензию. Коммерческий ключ **никогда не отправляется через Resend/email**.
- Чистый клиентский доступ к checkout требует HTTPS и **same-origin** проксирования `/v1/checkout/proeducation/*` в согласованный backend, без утечки приватного тела POST и без внешнего redirect. Существующая статическая публикация сайта и API должны быть проверены отдельно.
- Частичные/полные возвраты фиксируются в ручном защищённом журнале после сверки кабинета ProEducation: возврат не вызывается backend, лицензия не отзывается автоматически. Подтверждённый **полный возврат** блокирует последующую выдачу из `paid_hold`. У журнала есть отдельная аддитивная PostgreSQL-миграция, которую **нельзя выполнять автоматически**.
- Серверная активация блокирует строку лицензии в PostgreSQL: конкурентные запросы на 8 разных устройств не обходят лимит двух.

## Что подтверждают тесты (не live)

- Backend PR #26: синтетические PostgreSQL 17 / HTTP / HMAC / двойные webhooks / claim / возвраты / конкурентная активация; CI в GitHub, без merchant secret, реальных средств или production БД.
- Website PR #22: браузерные сценарии всех трёх языков, закрытый checkout, копирование номера и кода, восстановление существующего ключа по POST, отсутствие ключа в URL, отсутствие возможности подменить SYS/сумму.
- Синтетические тесты **не доказывают** корректность настоящего merchant callback, валюты списания, подписи релизного macOS клиента или наличия proxy на официальном домене.

## Обязательные условия для GO (выполнять в указанном порядке)

1. **Merchant:** подтверждён реальный режим ProEducation KZ для `anriprod.proeducation.kz`, согласованный `sys=anriaudio`, настоящий секрет подписи, реальный формат callback и фактическая валюта KZT. Историческую транзакцию с `currency=rub` и без `sys` не использовать как доказательство.
2. **Цена:** продавец утверждает конкретную сумму **в KZT** за лицензию $39; записать её только в защищённый `PROEDU_FULL_PRICE_MINOR_KZT`, проверить отображаемую цену на форме до оплаты. Не вводить синтетическую тестовую сумму.
3. **Issuer:** независимо извлечь Ed25519 public key из **релизного** AU/License Agent, сопоставить с issuer staging/production. Не считать pin из staging RC доказательством коммерческого клиента.
4. **Хранилище:** резервная копия действующей PostgreSQL и проверка восстановления, сверка исторических лицензий, таблиц и колонок, согласование миграции/rollback, затем изолированный read-only preflight. Не выполнять SQL из PR на production автоматически; не запускать несовместимую версию backend до миграции.
5. **Маршрутизация:** подтвердить все три официальных URL checkout и HTTPS **same-origin POST** к `/v1/checkout/proeducation/create` и `claim`; удостовериться, что исходный JSON body не теряется, запросы не переадресуются в чужой origin и ответы имеют `Cache-Control: no-store`.
6. **Платёжный цикл:** при включённом merchant live провести **отдельно разрешённую** минимальную реальную оплату с сохранением обезличенных доказательств callback, KZT, HMAC/Sign, одной лицензии и корректной активации без письма с ключом. Повтор callback, отказ и возврат — проверить без второго ключа.
7. **Публикация:** после отдельного разрешения обновить production сайт и backend только утверждёнными ревизиями и включить флаги в контролируемом порядке. Проверить публичные документы, поддержку, возвраты, релизный установщик и откат.

- Не сливать PR в main, не менять существующий Anri-cloud, Telegram webhook, действующие ключи, AUv2/Broker/SEND MIDI и ANRI DRUMS.
